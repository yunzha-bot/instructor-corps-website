## 连续滚轮适配

`src/rhine/wheel-track.ts` 与 `scene.ts` 的 wheelTrack 是新增部分：

1. 将鼠标／触控板输入按deltaMode归一化，保留原事件的缩放手势、横向输入、弹窗和详情状态边界。
2. 一块档案对应120像素滚动输入。输入直接累加到连续行坐标目标；不循环调用onNavigate模拟下一项。
3. 带速度的临界阻尼驱动实际行坐标，输入跟随rate18；停止输入160ms后目标吸附到最近整数行，收敛rate14。
4. 轨道Z位置随连续行坐标变化，逻辑选择通过原navigatePlane在跨越半格时跟随。新卡、旧卡副本和相邻波场继续由原场景驱动。
5. 正反向可连续衔接；小幅输入会累积。按键、点击、拖动、模式切换和失焦可取消滚轮轨道，避免两个运动驱动器争用同一属性。
6. 阅读详情不通过滚轮换档；内部文字滚动保留。减少动态设置采用简化行为。

用户曾指出滚动数字已经切换，但档案板抽出／跟随仍像延迟一拍。排查和手动调参时要区分两层：`wheel-track.ts` 的 `rate: 18`（输入跟随）与 `rate: 14`（停轮吸附）控制轨道；`scene.ts` 的 `lift` 阻尼分支中 `7.6`（浏览状态选中板升起）和 `4.2`（进入详情）控制档案板运动。调整前应先判断用户指的是轨道焦点还是板面抽出，避免把整个滚轮惯性一起改快。当前有连续轨道的自动检查，板面与数字的主观同步仍需结合用户设备复核。

## 首次渲染与可见卡顿

用户反馈上一轮预热后仍有卡顿、闪烁，并要求尽量在加载页完成准备。新增 `scripts/check-startup.mjs` 复现：旧首页在 ready 后仍新增 37 个着色器程序，一次帧间隔约 4.3 秒。仅等待原预热还不够：镜头外的选中档案没有经过实际后期渲染，抽出后继续补编译。此证据定位首入场卡顿，不能据此断言所有设备上的闪烁都只有一个原因。

当前所有启动入口都在连接遮罩下等待 `ArchiveScene.prepareRendering()`：先采用实际档案布局与正式渲染尺寸，初始化阵列、主题及阴影覆盖；异步编译后，临时关闭网格视锥剔除，实际渲染归位／抽出两种材质和清晰度状态，覆盖透射、阴影及 AO／景深后期通道。使用 WebGL2 fence 异步等待 GPU 完成上传和绘制，再恢复剔除、材质及入场状态，最后允许进入。字体同时按实际演示档案文字预加载。加载期间显示「正在准备档案画面…」，不使用固定延时冒充就绪；失败时保留浏览器运行时编译回退。

该处理把首次准备耗时移到加载页，不保证降低设备持续渲染的成本。自动化用独立 Edge 检查首页、直接档案、直接详情；进入后 5 秒及随后滚动／打开详情均未新增着色器程序，首入场未发现超过 100ms 的帧间隔。回归命令：`node scripts/check-startup.mjs`；最近机器实测数据保存于 `qa/startup/checks.json`，耗时不作为所有 GPU 的性能承诺。另以减少动态的稳定画面相邻截图检查静态闪烁。四视口与真实滚轮回归使用 `node scripts/final-faithful-qa.mjs`。

`?reference=1`核验夹具保留源站原始滚轮行为和内容，仅用于比较；普通页面使用用户要求的连续滚轮。

## 运动中的边缘闪亮（2026-10-19）

用户确认静止不闪，但运动时「档案板边缘、细线或阴影发抖闪亮」。这与启动补编译分开处理；不能用静止截图一致或帧率平稳作为运动画面不闪的证明。

定位到离屏抗锯齿缺口：`WebGLRenderer({ antialias: true })` 只覆盖默认帧缓冲，原 `EffectComposer` 两个离屏目标的 samples 为 0。`quality-renderer.ts` 现将原始抗锯齿路径的两个目标启用硬件 MSAA：通常最多 4 samples，超过 400 万物理像素最多 2 samples，并受 GPU 上限约束；SMAA 和超级性能模式保留各自路径。采样配置变化时释放旧目标，随启动预热分配新目标。没有改动材质颜色、动画或关闭阴影。

回归命令 `node scripts/check-motion-aliasing.mjs` 使用真实 ArchiveScene、固定抽出姿态、原始画质、960×540 / DPR1，比较 8 帧、每步镜头 X 位移 0.001 下的边缘像素变化；总 RGB 差值超过 90 计为一次大变化。本机旧 samples=0 路径为 191 次，修正路径为 82 次，减少约 57%；测试要求至少下降 25%。证据见 `qa/motion-flicker/diagnosis.json` 及 `legacy-no-aa-*`／`native-aa-*` 图片。此为窄范围抗锯齿回归，不保证所有 GPU、视角和材质运动都无闪烁，仍以用户浏览器体验核对。

用户确认减轻，但希望继续消除残余闪亮。第二轮对比发现，叠加 SMAA 没有在该测试中稳定改善；2× 超采样效果更好。当时为普通／高／极高画质增加默认 2× 稳定采样（先高分辨率渲染再缩小）；后续用户明确反馈卡顿，当前默认已由下方四档轻量方案取代。2× 超采样仍作为手动选项，不对文字 UI 做模糊滤镜。

当时同口径对照为无离屏 AA 193 次、上一轮原生 AA 83 次、2× 稳定采样 3 次。`check-motion-aliasing.mjs` 保留独立于当前预设的历史光学参数夹具，比较原生 AA 与手动增强采样；这不再是默认低档的质量承诺。这是固定姿态微位移测试，不能解释成实际滚动时所有闪烁减少固定百分比。高采样增加 GPU 与显存开销；不承诺所有机器都维持原有帧率。

高采样还暴露出直达预览的重复布局切换：预热后先切开场布局再切回档案，会使刚分配的缓冲被重建。直达档案现在保留预热布局，启动时直接选择最终模式，避免这一无意义的重分配。启动检查同时验证稳定采样设置确实改变渲染参数并在刷新后保存。

## 四档轻量画质（2026-10-19，当前默认）

用户反馈当前设置非常卡，要求低开销的低／中／高／极高滑动按钮。设置面板顶部已改为四位置原生 range 和可点击档位，支持键盘；拖动 input 只预览，释放 change 才应用一次，避免拖动过程中连续重分配。单独的超级性能开关已从浏览器面板移除，低档统一使用简化材质与直接渲染路径，模型运动保持开启。

| 低 | 60% 比例、1× 采样、简化材质，关闭阴影／AO／景深 | 921,600 |

### 各档画质的文字与照片清晰度分层

用户指出低档下图片和文字模糊。根因是 `resizeQuality()` 将整个 WebGL 场景按低档约 60% 比例绘制到较小缓冲，再由浏览器放大；右侧档案 UI 是独立 DOM，因此不受这项缩放影响。板面上的贴纸照片和编号牌则属于三维网格／CanvasTexture，会随 WebGL 缓冲一起变软。

所有画质档位在打开档案时，`NativeCanvasOverlay` 都把贴纸原 Canvas 和档案编号牌 Canvas 作为 DOM 画布显示，并根据它们各自的三维网格四角、相机投影计算 projective `matrix3d`，每次场景重绘时跟随平移、旋转与透视。对应 WebGL 网格隐藏，避免重影；照片的点→线→面遮罩同步映射到 CSS clip-path，暗色点线继续保留。离开详情后，DOM 层隐藏并恢复原 WebGL 网格。

该路径不创建额外 WebGL pass、不改变任何档位的渲染像素预算。低档实测 buffer 为 775×711、预算仍为 921,600；中／高／极高继续使用各自原有的缓冲尺寸、阴影、AO、景深和后处理，但照片与编号牌不再跟随 WebGL 画面降采样或全场景景深变软。其余外壳、光盘和背景仍按各档渲染。Playwright/Edge 逐档打开详情后均观察到两块透视叠层可见、照片揭示已完成且无页面错误；按 Esc 返回浏览模式后，两层均隐藏。截图位于 `qa/native-overlay-tiers/`。360° 模型查看器仍走其自身渲染路径，未纳入这次清晰度叠层。

### 低档滚轮后的归位暗影

用户圈出滚轮切档后背景出现、数秒后消失的深色区域。复现时实时阴影已经关闭，但 outgoing 旧档案仍用完整光学副本绘制，直到归位后销毁；周围阵列则使用低档不透射的简化材质，造成临时色差。

低档现在隐藏旧档案光学副本，把其归位位置和旋转写入已有简化实例批次；归位轨迹不变，最终回归普通阵列。其他画质保留原返回副本路径，切换路径时同步可见性和实例排除，避免重复板面。本次不增加阴影、AO、景深或渲染分辨率。

回归：`node scripts/check-low-return.mjs`，证据 `qa/low-return/`。先用真实滚轮产生归位档案，再验证低档无可见光学副本、旧位置仍在实例批次、实例矩阵与原归位姿态一致、切换回完整路径及归位销毁正常；不是只检查阴影开关。

用户后续指出持续下滚时前排仍会短暂出现深色块。上一轮只覆盖 outgoing：当前新选中的板面仍绘制完整光学材质，连续切档时反复在两类材质间切换。低档浏览现把当前板面也按实际位置／旋转写入同一简化批次；进入详情及详情过渡期间恢复完整模型，加载时仍预热其材质，避免首次打开补编译。

另一个低档干扰是连续选择叠加的装饰性传播波浪，会抬起前排并露出深色侧面。低档不再发射该脉冲，切入低档时清空存量脉冲；轨道、焦点抬起、归位和详情运动保留，其他画质的选择波浪保留。连续 120 帧回归新增当前板面始终在简化批次、无完整材质回切、无脉冲叠加的检查，并验证详情仍显示完整模型。不能再把仅有 outgoing 检查当作连续滚动问题已全部覆盖。

### 详情移动噪点与较高画质核验

用户补充低档下滚轮／抽出、归位及详情左右拖动均会见到噪点，并要求检查中／高／极高。诊断区分完整板面的正常折射变化与内部结构显现时的随机像素遮罩。原 `CardAppearance` 用 `gl_FragCoord` 哈希 discard 做显现，物体运动时会产生颗粒式变化；已改为连续 alpha 渐变，同时保持 `transparent=false`，确保内部结构仍参与外壳透射捕获。原本不透明的内部材质使用受控混合，保留深度写入；完全隐藏时仍 discard，完整显示时保留原色与几何。没有采用实验中效果不稳定的 alpha-to-coverage 路径。

低档详情的透射捕获从 1/4 分辨率改为最低 1/2，仅作用于实际有透射的打开板面。低档周围阵列依然使用不透射的简化材质；主画面比例、像素预算、阴影／AO／景深开关均不变。该小捕获会增加少量详情渲染工作，不等于完全零成本。

`node scripts/check-detail-grain.mjs`：使用实际 Internal_Ceramic 材质、半显现和小角度转动，隔离外壳折射、环形结构视差及轮廓的正常变化。将采样点映射回物体坐标后，比较连续帧亮度变化；本机旧遮罩大跳变 67 次，连续渐变 18 次（17,885 个比较样本），要求至少下降一半。证据 `qa/detail-grain/diagnosis.json` 及 legacy-mask／production 截图；不能把该窄范围结果当成整页所有噪点的改善百分比。

`node scripts/check-upper-quality.mjs`：中／高／极高分别执行真实连续滚轮、点击抽出、指针拖动、解密完成、旋转归位与返回，并检查渲染预算和浏览器错误；最近三档均通过。证据 `qa/upper-quality/checks.json` 与各档阶段截图。该检查覆盖已测试操作，不是所有设备、所有交互的无缺陷保证。

# 档案详情右侧视觉优化

模式：Redesign / Preserve。以现有截图与 src/rhine 的可运行页面为视觉目标，对右侧正文体系作统一优化。

保留：灰白档案配色、MiSans、用户图片及光盘、三维场景、40块档案、目录顺序、轮轨与分类、直接填写、字段顺序、保存键、草稿、键盘和仅浏览器演示说明。官网首页不在本轮。

改善：主标题字重和行距；标签、内容、状态三级层次；字段分组和留白；底线与分隔线强度；输入焦点／悬停／保存反馈；桌面与手机的阅读尺寸。

移除：标题后的粗黑分隔线、所有字段同时抢眼的长横线、焦点硬框及原生大号下拉外观。采用轻薄纸页感，避免大圆角卡片、阴影堆叠与额外科技装饰。

设计判断：当前粗线、重字和输入区的统一底线形成机械表格感；右侧字级随整场缩放，部分视口过大、部分过小。采用单独的阅读字级、较轻标题、少量发丝线、柔和而克制的局部纸色，聚焦时才强调可编辑区域。

设计刻度：视觉变化 3/10、局部动效 3/10、内容密度 5/10、素材依赖 9/10、品牌保真 10/10。

交互：页签内容以约 220ms、4px 的轻微上移淡入衔接；聚焦时纸色与底线柔和加深；保存文字回馈短暂出现。全部尊重减少动态与现有 surfaceTransitions 偏好。没有常驻动画或新增 WebGL 工作。

接口：沿用 inlineRecordForm / bindInlineRecords，让所有40块详情共享同一排版样式；视觉规则集中至 detail-editor.css，不在各档案中复制样式或增加页面分支。

风险与回退：只作用于 editable-dossier，不改变 reference 对照模式和场景坐标；交互验证沿用真实浏览器保存／刷新／跨档案检查，截图固定视口和状态做前后对照。

证据：profile-prototype/qa/detail-polish/before、after；覆盖技能、总览、训练、记忆、相关文档、焦点、2560宽屏和390手机。内置浏览器 iab 当前不可用，使用用户此前已授权的独立 Playwright/Edge 进行核验。


验收记录：已对照同视口技能页前后画面，并查看个人总览、关联文档、宽屏与手机版；标题由700降为400，重横线移除，字段和主次操作层级统一。暗色沿用主题变量。原位填写全流程、目录顺序与连续滚轮、类型及构建均通过；表单聚焦尺寸不变、页签220ms/4px、关闭动态无内容动画、快速切换与收藏切换由独立脚本核对。无新增依赖或场景工作量。

详情阅读时隐藏右下重复英文署名，防止较长表单及收藏／导出与固定署名重叠；浏览和开场署名保留。
